# Среда Codex

Настройка относится к этому репозиторию. Общие пользовательские настройки,
модель, уровень рассуждений и разрешения среды не переопределяются.

## Где что хранится

| Файл | Назначение |
|---|---|
| [`AGENTS.md`](../AGENTS.md) | Общие правила работы, выбор навыков и достаточные проверки |
| [`.agents/skills/`](../.agents/skills/) | Четыре навыка: workflow, LaTeX, TikZ и проверка физики |
| [`.codex/agents/physics-reviewer.toml`](../.codex/agents/physics-reviewer.toml) | Независимая проверка физики и полноты решений |
| [`.codex/agents/latex-reviewer.toml`](../.codex/agents/latex-reviewer.toml) | Проверка исходников, журналов и подготовленных изображений PDF |
| `materials/<type>/<slug>/PLAN.md`, `WORKLOG.md` | Согласованный объём, текущий этап и история конкретного материала |
| [`docs/SETUP_LOG.md`](SETUP_LOG.md) | История настройки самого проекта |

Корневой `AGENTS.md` содержит постоянные правила; подробности загружаются из
нужного навыка. Это соответствует документированным механизмам
[инструкций проекта](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
и [обнаружения skills](https://learn.chatgpt.com/docs/build-skills).

Роли проверяющих не редактируют материалы и не утверждают этапы. Основной агент
передаёт им конкретный вопрос и собирает результаты. Для проверки PDF он заранее
готовит сборку и растры в `output/`. Файлы ролей не задают модель или reasoning:
эти значения наследуются от основного агента. Поддержка именованных ролей зависит
от клиента; контракт роли можно передать обычному субагенту.
Схема файлов взята из [документации subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Как ставить задачи

Полезно указать материал, ожидаемый результат, источник данных и границу правки.
Например:

```text
Исправь обрезку схемы в materials/labs/<slug>/, сохрани физический смысл.
Собери обе версии и проверь изменённые слайды. Статус этапа не меняй.
```

```text
Используй $physics-content-review для проверки задачи 6 и её решения
в materials/labs/<slug>/. Сопоставь с source/, проверь системы отсчёта
и единицы. Верни замечания с указанием файлов; исходники не меняй.
```

```text
Утверждаю этап 2 для <slug>. Переходи к черновику по согласованному плану.
```

Однозначная команда перехода уже считается подтверждением по
[рабочему процессу](WORKFLOW.md). Техническое обслуживание не меняет стадии.

## Основание настройки

Проверено 2026-09-09 по разделу GPT-6 Astra в
[Model guidance](https://developers.openai.com/api/docs/guides/latest-model).
Применены рекомендации о самостоятельном завершении задач, ясных границах
подтверждений, точечном делегировании, краткой коммуникации и проверках по масштабу
изменения. Рекомендации перенесены в правила проекта с сохранением его ручных
контрольных точек. API-параметры сюда не перенесены: проект выпускает LaTeX-материалы
и не содержит приложения, вызывающего OpenAI API.

После изменения `AGENTS.md` или файлов ролей начни новую сессию в этом репозитории.
Skills клиент обнаруживает автоматически; если обновление не видно, перезапусти
его. Можно попросить перечислить загруженные инструкции и доступные навыки.
Это проверяет фактическое обнаружение клиентом, тогда как разбор YAML/TOML
проверяет только файлы.

## Ограничение сборочной среды

Требование проекта — закреплённый Docker-образ. Сейчас `Makefile` использует
`ghcr.io/slauva/master-thesis-2024-2026/latex:latest`: это изменяемый тег,
а не фиксация по digest. Настройка агентов не меняет сборочный образ.
Для фиксации нужен проверенный digest используемого образа; его нельзя выдумывать.
До этого точная воспроизводимость между разными загрузками `latest` не гарантирована.
