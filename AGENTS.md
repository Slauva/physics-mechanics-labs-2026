# Инструкции проекта

Проект предназначен для англоязычных учебных материалов по механике: лабораторных работ, презентаций, тестов и списков задач.

## Как вести работу

- Общайся с пользователем по-русски, если он не выбрал другой язык. Кратко сообщай результат, изменённые файлы, проверки и оставшиеся ограничения.
- Сначала проверь `git status --short` и относящиеся к задаче файлы. Сохраняй чужие изменения. Для продолжения материала прочитай его `PLAN.md` и последние записи `WORKLOG.md`; не восстанавливай статус по памяти чата.
- Выполняй запрос до проверяемого результата внутри разрешённого этапа. Обычные технические решения принимай самостоятельно; спрашивай, если ответ меняет физический смысл, исходные данные или согласованный объём.
- Явные указания пользователя имеют приоритет над рекомендациями skills. Уже данное однозначное подтверждение этапа занеси в журнал и используй без повторного запроса. Молчание подтверждением не является.
- Настройка среды, документации и skills, а также изолированная техническая правка не запускают новый цикл согласований материала и не меняют его статус. Изменение содержания проходит контрольные точки ниже.
- Если правило требует остановки, укажи точный файл, процитируй правило и объясни, какое решение нужно. Сначала подготовь все доступные результаты текущего этапа для проверки.

## Работа с материалами

- Для нового материала или существенной переработки используй skill `physics-material-workflow`.
- Для набора, сборки и исправления LaTeX используй skill `physics-latex-authoring`.
- Для схем и рисунков TikZ используй skill `physics-tikz-figures`.
- Для проверки формул, решений, единиц и педагогической полноты используй skill `physics-content-review`.
- Skills находятся в `.agents/skills/<name>/SKILL.md`. Загружай только подходящий skill и нужные ссылки из него. Этапы описаны в `docs/WORKFLOW.md`, оформление — в `docs/DESIGN.md`, устройство среды — в `docs/CODEX.md`.
- Исходные файлы преподавателя в `source/` считаются неизменяемыми. Производные материалы создавай рядом, но не перезаписывай оригиналы.
- Весь текст, видимый в итоговых PDF, включая заголовки, задания, решения, подписи, легенды и TikZ-метки, пиши только на английском. Входные материалы и рабочая документация могут быть на другом языке.
- Каждый материал веди по `PLAN.md` и `WORKLOG.md`. Не переходи через контрольную точку без явного подтверждения пользователя. Подтверждение заноси в журнал.
- Лабораторные работы оформляй как Beamer-презентации 16:9 через `physicslabslides.cls`, а не как A4-документы.
- Если в материале есть задачи или вопросы с ответами, поддерживай обе версии: `main.tex` без решений и `solution.tex` с решениями. Общий текст держи в `content.tex`.
- Не выдумывай экспериментальные данные, условия, формулы или ответы. Неясности выноси в план как вопросы.

## Параллельная работа и память проекта

- Делегируй независимую проверку источников, физики или макета, когда это ускоряет работу или улучшает качество. Не дроби мелкую правку ради нескольких агентов.
- Для проверки доступны роли `.codex/agents/physics-reviewer.toml` и `.codex/agents/latex-reviewer.toml`. Если клиент не поддерживает именованные роли, передай соответствующий контракт обычному субагенту.
- Передай помощнику конкретный вопрос, исходники, границы проверки и ожидаемый результат. Разделяй владение изменяемыми файлами; сборку и запись общих журналов координирует основной агент. Проверяющие возвращают замечания и ничего не утверждают от имени пользователя.
- Долговременные решения материала храни в `PLAN.md`, фактическую историю — дописывай в `WORKLOG.md`. Изменения среды записывай в `docs/SETUP_LOG.md`. Не создавай параллельный журнал статусов и не помещай текущую стадию конкретной лабораторной в общие инструкции.

## Сборка

- Используй цели `make`, которые запускают закреплённый Docker-образ. Не полагайся на локальную установку TeX.
- Генерируемые PDF, логи, растры страниц и извлечённый текст должны находиться только в `output/`. Исправляй исходники, затем пересоздавай результат.
- Перед передачей результата выполни `make lint` и собери изменённые точки входа.
- После успешной сборки визуально проверь PDF: переполнения, обрезку, читаемость с проектора, нумерацию, единицы измерения, английские подписи и отсутствие кириллицы. Для лабораторных и презентаций отдельно проверь формат 16:9.
- При изменении общего `content.tex` или рисунка собери обе использующие его версии. Для общих классов и темы выполни `make check` и собери затронутые материалы: `make check` охватывает только шаблоны и демонстрации.
- Для изменений только Markdown, skills и конфигурации достаточно `make lint` и проверки изменённых форматов и ссылок; пересборка PDF не требуется. Изменённые скрипты проверь на соответствующих сценариях. Не расширяй и не повторяй успешные проверки без новой причины.
- При недоступном Docker или просмотре PDF сообщи, какая проверка не выполнена. Успешный lint не заменяет сборку, визуальную проверку или утверждение содержания.
